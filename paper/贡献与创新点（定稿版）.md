## 第一部分 · 模型事实：代码里真实存在的是什么

`stage_final` 本身只有 14 行，它是一个组合体：把 `stage_MOE`（专家混合）、`stage_MOE_PT`（PT→PHT 门控迁移）、`stage_MOE_consis`（一致性损失）三条已完成的分支合到同一个前向与同一个损失里。

```
source/plm_unified/stage_final_model.py        # 继承 StageMOEPTBindingModel，复用 consis 的 forward_batch
source/plm_unified/stage_MOE_model.py          # 交互块 + 共享/专属专家混合
source/plm_unified/stage_MOE_PT_model.py       # PTFusion：HLA 条件化的残基级门控迁移
source/plm_unified/stage_MOE_consis_loss.py    # 四类标签感知的方向性 hinge
configs/plm_stage_final.yaml                   # 全部超参的唯一来源
```

### 1.1 骨架（贡献一的载体）

- **冻结 PLM**：肽/HLA 用 ESM-C 300M（hidden 960），TCR CDR3β 用 TCR-BERT（hidden 768）。两者参数不在优化器里，残基嵌入预先算好写进分片定宽 HDF5 缓存。下游 `model_dim = 256`，8 头，三层 `SequenceEncoder`。
- **端到端序列级三关系分支** `ph / pt / pht`，不依赖外部异构交互图；每个分支一个交叉注意力块，**肽永远是 query**，所以输出始终保留肽残基轴（`stage_MOE_model.py:21`，`AttentionResidual`）。
- **该块没有普通的前馈子层**——前馈子层的位置正好被专家混合占用（`stage_MOE_model.py:21-39` 对比 `:45-63`）。这一点是贡献二在架构上成立的前提。

### 1.2 专家混合（贡献二的载体）

| 事实 | 代码位置 |
|---|---|
| 每个分支私有 2 个专家 | `stage_MOE_model.py:49`（`for _ in range(2)`，**硬编码**） |
| 全局共享 2 个专家，整模型只注册一次，三个关系共用 | `stage_MOE_model.py:99` |
| 路由器输出维度 4 = 2 共享 + 2 专属 | `stage_MOE_model.py:51` |
| 门控 = softmax(router(context)/τ)，fp32 计算 | `stage_MOE_model.py:58` |
| 稠密混合：四个专家全部求值后加权求和，无 top-k、无容量限制 | `stage_MOE_model.py:60-61` |
| **门控按样本算一次、所有残基位置共用**（路由是 sample-level，专家计算是 residue-level） | `stage_MOE_model.py:58, 61` |
| 路由上下文 = 本关系交互输出的掩码均值 ⊕ 各实体均值；成对关系 3×256，三联 4×256 | `stage_MOE_model.py:101, 109` |
| 专家本身 = 两层 `Linear-GELU-Linear`，内宽 512 | `stage_MOE_model.py:41`，`configs/plm_stage_final.yaml: expert_hidden_dim: 512` |
| 温度退火 2.0 → 1.0，5 个 epoch | `plm_stage_final.yaml: temperature_start/end/epochs` |
| **路由均衡正则权重为 0**，即该机制在默认配置下不激活 | `plm_stage_final.yaml: balance_lambda: 0.0`；罚项定义在 `stage_MOE_consis_loss.py:62` |

关键结构性事实：三联分支的 query 是 **PH 分支的专家输出 `zph`**，不是 PH 的注意力输出，也不是池化向量（`stage_MOE_model.py:144, 148`；启用迁移时 `stage_MOE_PT_model.py:66-72`）。这使"被门控选中的变换继续进入三联关系"成为代码事实而非修辞。

### 1.3 PT→PHT 门控迁移（贡献三的载体）

| 事实 | 代码位置 |
|---|---|
| 三联分支先做 `zph → t` 的交叉注意力，再把 **PT 分支未池化的残基表示 `zpt`** 以残差形式注入 | `stage_MOE_PT_model.py:71-72` |
| 门控输入 = [三联状态, 归一化 PT 状态, **广播的 HLA 摘要**]，共 3×256 维 | `stage_MOE_PT_model.py:26, 34-35` |
| β 逐残基、sigmoid、填充位置置 0，形状 `[B, L_P]` | `stage_MOE_PT_model.py:36` |
| 融合式 `fused = query + β ⊙ W·LN(zpt)` | `stage_MOE_PT_model.py:38` |
| 门控偏置初始化 −2.0 ⇒ **β 初始 ≈ 0.12**，迁移从"几乎关闭"开始 | `stage_MOE_PT_model.py:27`；`plm_stage_final.yaml: fusion_bias_init: -2.0` |
| 迁移可整体关闭（唯一现成的消融开关） | `stage_MOE_PT_model.py:56-61`；`plm_stage_final.yaml: pt_fusion_enabled` |
| β 随输出返回，可直接做分析 | `StageMOEPTOutput.fusion_beta` |

### 1.4 标签感知的方向性一致性（贡献四的载体）

四条 hinge 全部是 `φ(a,b) = relu(a − b − m)²`，`m = 0.05`，**每条都对"标签指定的参照端"加 `detach()`**（`stage_MOE_consis_loss.py:49-57`）：

| 名称 | 生效条件（标签类） | 被推动的一端 | 被冻结的一端 |
|---|---|---|---|
| `hierarchy_positive` | `111` | PH 概率 ↑ | 三联概率 |
| `hierarchy_negative` | PH=0 且 PHT=0（`000`/`010`） | 三联概率 ↓ | PH 概率 |
| `pt_positive` | `111` | PT 概率 ↑ | 三联概率 |
| `pt_negative` | PT=0 且 PHT=0（`000`/`100`） | 三联概率 ↓ | PT 概率 |

- 四类标签合法集合 `{000, 010, 100, 111}` 由校验器强制，**出现 `110` 直接抛错**（`stage_MOE_consis_loss.py:41-46`）。这是全文最大的论证风险，见第七部分。
- 辅助 PH/PT 的 BCE 权重各 0.1，在三联批次上同时施加（`stage_MOE_consis_loss.py:32-33`）。
- 一致性权重按 epoch 线性 ramp：warmup 3 epoch 后在 5 epoch 内升到 `hierarchy_lambda=0.05` / `pt_implication_lambda=0.03`（`stage_MOE_consis_loss.py:25`，`StageFinalSettings.consistency_ramp`）。

## 第二部分 · 贡献清单与三机制分工

> 论文 `main.tex` 的 Introduction 已同步更新为以下五条贡献，编号与全篇定位表、方法小节、消融表及结论完全对齐。

1. **端到端序列级 PH / PT / PHT 三任务统一建模，并以 `110`/`111` 数据不对称论证显式三元任务的必要性**：在冻结 PLM 残基嵌入之上，不依赖外部异构交互图（区别于 [UniPMT](https://doi.org/10.1038/s42256-025-01002-0)）统一预测三个关系；指出由于现有语料缺失 `110` 难负样本、正样本全为 `111`，容易制造“二元成立即可推出三元成立”的假象，因此必须保留显式三元分支并与自身二元头的启发式组合（$s_{\min}$、$s_{\mathrm{prod}}$）直接对照。
2. **关系条件化的共享—专属 MoE，解决二元与三元任务冲突**：剖析 [UnifyImmun](https://arxiv.org/html/2405.06653v2) 与 [Fusion-pMT](https://arxiv.org/html/2501.01768v1) 静态参数共享引发的二元—三元任务冲突；在每个交互块前馈子层位置、沿肽残基轴放置“2 全局共享 + 2 分支专属”逐位置专家并由样本级关系门控稠密混合，以共享门控占比 $\alpha_r$ 接受经验检验。
3. **HLA 条件化的残基级 PT→PHT 门控迁移，实现 PT 与 PHT 双向优化**：对比仅做 PH→PHT 迁移的 [Fusion-pMT](https://arxiv.org/html/2501.01768v1)，指出 PHT 是受 PH 与 PT 共同支配的双结合过程，因此独立 PT 交互特征迁移同样必要；前向逐残基按 HLA 语境选择性注入识别证据优化 PHT，反向通过可微门控回传受调节的 PHT 监督梯度优化 PT 表征（已在消融实验中证实同步提升 PT 与 PHT）。
4. **标签感知的方向性一致性目标，消除输出空间逻辑矛盾**：四项带容差 $m$ 的软平方 hinge 按观测标签类选择性激活，通过 `stop-gradient` 冻结标签指定的参照端、仅更新自身标签支持的一端，在避免硬概率层级约束（如硬 $\min$ 投影）过约束与误差传播的前提下降低跨头违约率。
5. **（经验性贡献，待实验填充）** —— `stage_final` 完整主实验尚无结果，此条在论文中仍是 `\TODO`。

### 三套核心机制的层次分工（互不重叠、逐层互补）

| 机制（对应贡献） | 作用层次 | 解决的核心问题 |
|---|---|---|
| **共享—专属 MoE**（贡献二） | 参数与表征空间 | 解决跨任务（尤其是二元 PH/PT 与三元 PHT）的参数竞争与梯度冲突，在不泄露缺失模态的前提下共享通用肽特征、隔离任务专属模式 |
| **HLA 条件化 PT→PHT 门控迁移**（贡献三） | 跨分支特征与梯度流 | 补齐三元分支缺失的识别侧残基级特征（前向优化 PHT），同时将受 HLA 门控调节的 PHT 监督反馈回 PT 表征模块（反向优化 PT，抑制 `010` 负迁移） |
| **标签感知方向性一致性**（贡献四） | 输出与决策空间 | 解决三个独立分类头在预测概率层面的逻辑自相矛盾（如低 PH 却高 PHT），在尊重各头独立校准的同时避免硬层级约束的误差传播 |

## 第三部分 · 贡献一：序列级三任务统一建模与 `110`/`111` 三元必要性论证

### 3.1 与 UniPMT 的核心区分

[UniPMT](https://doi.org/10.1038/s42256-025-01002-0)（Zhao et al., *Nature Machine Intelligence*, 2025；[PDF 全文](https://d-nb.info/137009602X/34)）虽在同一框架内覆盖 P–M（PH）、P–T（PT）与 P–M–T（PHT），但与本工作存在三条本质差异：

1. **无外部交互图依赖的序列级泛化**：UniPMT 依赖外部汇总异构图上的 GraphSAGE 消息传递，各任务训练时均需检索其余两类边构图，导致在缺乏历史邻域的未见肽（zero-shot）场景下泛化明显受限（P–T zero-shot ROC-AUC 降至 61.59%–62%）；本工作直接从冻结 PLM 残基嵌入端到端预测三个关系，不依赖图连通性。
2. **对称的三关系建模与显式三元残基交互**：UniPMT 中 P–M 仅单向向 P–M–T 传递表征（消融表明对 P–M 无反向增益），P–M–T 仅用 P–M 与 M–T 两个二元向量的双线性乘积（DMF）近似，而 P–T 不设独立分支、仅对全部候选 MHC 的三元概率等权平均（忽略 HLA 限制性）；本工作保留独立受监督的 PT 分支并在肽残基轴上直接建模三元交互。
3. **直面 `110`/`111` 边界而非依赖随机负采样捷径**：UniPMT 的标准三元评测主要采用“固定肽段、随机打乱 MHC 与 TCR”的简易负样本（大量负样本可仅凭 P–M 不结合捷径排除）；当固定 P–M 消除捷径后，其新抗原测试集 PR-AUC 从 72% 骤降至 28.36%。

### 3.2 通过缺失 `110` 难负样本论证显式三元任务的必要性

- **生物学现实**：同一肽段可以同时满足被 HLA 呈递（PH=1）并在序列层面匹配 TCR（PT=1），但仍可能因 HLA 槽内构象不兼容或空间位阻而无法形成稳定三元复合物（`110` 难负样本）。
- **数据假象**：现有公开语料几乎不含经验证的 `110` 样本，正三元组全部表现为 `111`。若把 `111` 语料当成完整现实，逻辑合取（$\text{PH}=1 \land \text{PT}=1 \Rightarrow \text{PHT}=1$）就会看似平凡成立，从而掩盖专门建模三元任务的必要性。
- **方法与实验闭环**：因此在统一框架中必须保留显式三元分支以捕获三体协同作用，同时在主实验表与消融表中纳入由本模型自身二元头算出的启发式组合 $s_{\min}=\min(\hat y_{\mathrm{PH}},\hat y_{\mathrm{PT}})$ 与 $s_{\mathrm{prod}}=\hat y_{\mathrm{PH}}\hat y_{\mathrm{PT}}$ 以及 `100 vs 000`、`010 vs 000` 诊断列，诚实检验三元头在当前语料下的真实增量。

## 第四部分 · 贡献二：关系交互层的共享—专属专家混合（解决二元—三元冲突）

### 4.1 定位：这不是机制创新，是冲突分析与适配性论证

共享专家 + 任务专属专家 + 稠密 per-task 门控的拓扑，**是 CGC/PLE 的设计**（Tang et al., RecSys 2020），我们原样采用，`2 + 2` 的专家数在该方案里只是一个超参取值。论文明确把它写成"**冲突分析、应用与放置上的空白，而非机制上的空白**"。

前人静态共享架构在统一建模二元（PH、PT）与三元（PHT）任务时会产生直接冲突：
- **[UnifyImmun](https://arxiv.org/html/2405.06653v2)（过度分解 + 共享肽段冲突）**：仅共享一个 1 层 1 头的浅层肽编码器，在 PH 与 PT 两个并行交叉注意力分支间交替冻结训练，且无 HLA–TCR 交互通路与三元头；PH 锚定特征易渗入 PT（原文热图中 pTCR 仍将 HLA 锚定位 P2 判为最关键残基），且无法建模三元协同。
- **[Fusion-pMT](https://arxiv.org/html/2501.01768v1)（过度绑定 + 全参覆写冲突）**：三类分子共享同一线性投影矩阵 $\bm{W}$，阶段一预训练 PH 后丢弃 PH 头并在 PHT 上全参数微调（且无独立 PT 分支）；由于大量 PHT 负样本是有效的 HLA 结合肽（PH=1, PHT=0），三元负样本梯度直接覆写呈递骨干，诱发灾难性遗忘与二元—三元梯度正面碰撞。

### 4.2 任务为什么需要这个分解（四条，通俗直观版，已同步写入 `main.tex` 第 3.4 节）

**(1) HLA 与 TCR 读取同一肽段的不同区域。** 短肽嵌在 I 类 HLA 结合槽内时，HLA 固定肽段两端的锚定位点，而 TCR 从上方识别朝向外界的中部暴露区域（Rudolph et al., 2006）。因此呈递与识别既共享基础肽属性（氨基酸组成、长度与整体柔性），又依赖截然不同的结合区域；单一共享变换会被拉向两个方向，完全独立则浪费了共通监督，共享 + 专属专家正好对应这一分工。

**(2) 二元与三元标签在共享权重上方向相反。** HLA 结合先将肽段弯曲成等位基因特异的构象，且大量高亲和呈递肽（PH=1）并不被特定 TCR 识别（PHT=0）。静态共享或全参数微调会让三元负样本梯度覆写呈递特征；分支专属专家把呈递、识别与三元协同隔离到独立参数子空间，同时保留共享专家提取通用肽表示。

**(3) 共享与专属的比例随样本变化。** 呈递完全由两端锚定位主导的肽，两事件近乎解耦；中部残基同样影响结合槽稳定性的肽则高度耦合。**逐样本门控能按样本动态调节共享/专属比例，固定架构划分不能。** 这给出可检验的预测（见 4.5）。

**(4) 肽残基轴是输入不对等条件下的唯一共享工作区（最强，也最特属于本问题）。** PH 必须在无 TCR 时可预测，PT 必须在无 HLA 时可预测。因为肽永远是每个交叉注意力块的 query，**肽残基轴上的逐位置专家恰好是所有三个关系都能用自身输入触达的唯一模块**，既不泄露缺失实体，又保留残基轴使 `zph` 能直接流入三联分支。

### 4.3 相对前人工作：逐条"他们做到了什么 / 限制在哪 / 我们如何适配本任务"

#### MMoE（Ma et al., KDD 2018）

- **已做到**：一个共享专家池 + 每任务一个 softmax 门控；并且已经把"每任务的门控权重分布"当作诊断量来报告。
- **限制**：没有任务专属专家，关系特异的化学无处安放；专家作用在池化向量上。
- **我们的位置**：保留 per-task 门控与这个诊断量，补上专属专家。**门控分布诊断不是我们的发明**，论文里已显式声明。

#### CGC / PLE（Tang et al., RecSys 2020）—— 拓扑的出处

- **已做到**：共享专家模块 + 每任务专属模块，稠密 per-task 门控融合；为治"跷跷板效应"而提出。**这就是我们用的拓扑。**
- **限制（针对本任务而言）**：
  - 它把共享/专属分解当作"竞争任务的通用解药"**假设**下来，没有问某个具体问题是否真有这个结构；
  - 专家是**池化向量上的 MLP**，混合输出直接喂任务 tower 或下一层同类抽取层；
  - 门控是共享输入的线性函数（PLE 高层门控用的是该任务自己上一层的融合输出）。
- **我们的三条差异**：
  1. **共享发生在输入组成不同的关系之间**：共享专家被三个读取不同实体组成的分支更新，而非被共享同一输入的多个任务更新。
  2. **专家是逐位置的，输出保留残基轴**，流入后续交互计算后才池化；被选中的变换**继续进入三联交互**，而不是被池化成向量喂给 tower。
  3. **门控条件是它所服务关系的摘要**（当前配对的交互表示 + 各实体摘要），不是原始输入特征。这也正是 PH 推断看不到受体、PT 推断看不到等位基因的实现机制（`stage_MOE_model.py:109`）。
- **必须预先澄清的一点**：PLE 也在**异构样本空间**上评测过——用户必须先点击某个曝光，才可能观察到分享或转化。但那种异构性在**标签空间**且是**嵌套的**：所有任务读同一份 user–item 特征，差别只在哪些样本带标签。我们的异构性在**输入空间**且**不嵌套**：PH 分支永远收不到受体，PT 分支永远收不到等位基因，所以共享专家是被"建立在不同实体之上的表示"算出的梯度更新的，而不是同一表示在不同标签覆盖下的梯度。**推荐系统的结果不能回答共享专家池在这个条件下是否仍然有效。**

#### NeoMUST（Ma et al., 2024）—— 同领域最近的用法

- **已做到**：把 CGC 层用在两个 peptide–MHC 任务（呈递分类 + 亲和力回归）上，外加不确定性任务加权与冲突回避梯度下降。
- **限制**：两个任务读**同一个输入对**，所以它的机制从未被要求在输入范围不同的关系之间共享容量——而这正是本任务里更难的情形；它也只在 PH 层级，没有三联关系。
- **我们的位置**：三个输入不同的关系。**我们不做任何梯度手术，因此不声明在处理梯度冲突上优于它。**

#### MoE-TCR（Qu et al., 2026）

- **已做到**：把专家混合用于受体–表位预测。
- **限制**：专家是**整体预测器**，由按表位条件的稀疏 top-k 门控选择；**表示层面没有任何共享**。
- **我们的位置**：专家在交互块内部、作用于残基分辨的表示、稠密混合、且专家池的一部分跨关系共享。

### 4.4 一条需要自己先说出口的让步

把混合放进注意力块的前馈子层位置，在稀疏专家 Transformer 那条线里是**标准做法**（Shazeer et al. 2017；Fedus et al. 2022）。所以"逐位置专家"本身不特别；特别的是它与**共享/专属划分 + 关系条件门控**的组合，以及输出继续参与交互而不是喂 tower。论文里按这个措辞写，不夸大。

同样地：我们取的是多任务动机而非扩容动机——专家小、混合稠密、目的是分离"关系通用"与"关系特异"的交互化学，**不是廉价加容量**。因此**不对稀疏专家层做任何效率声明**。

### 4.5 可检验的预测，以及为此需要的消融

因为共享专家占据混合中的固定位置（`stage_MOE_model.py:60` 的拼接顺序 `(*shared, *private)`），共享比例可以直接读出：

$$\alpha_r = g_{r,1} + g_{r,2}$$

**如果上面的分解对这个问题是对的，那么：**

- P1：$\alpha_r$ 应在三个关系之间**系统性不同**；
- P2：$\alpha_r$ 应在同一关系内**随样本变化**；
- P3：去掉共享半边或专属半边，代价应**大于**去掉等量的无差别容量。

**预先承诺（已写进论文 Results）**：如果 $\alpha_r$ 在三个关系之间、以及关系内的样本之间都是平的，那就说明门控没有在用这个分解，诚实的结论是收益（若有）来自扩容。把这条写进去比等审稿人问出来要好。

## 第五部分 · 贡献三：HLA 条件化的残基级 PT→PHT 门控迁移（双向优化 PT 与 PHT）

### 5.1 动机：对比 Fusion-pMT 的双结合必要性

[Fusion-pMT](https://arxiv.org/html/2501.01768v1)（Ma et al., 2025）意识到了将独立 PH 任务学到的未池化交互特征传递给 PHT 的价值；虽然这种 PH→PHT 顺序符合“先呈递再识别”的生物学过程，但 **PHT 本质上是受 PH 与 PT 共同支配的双结合过程**。仅做 PH→PHT 迁移会让三元分支缺失独立 PT 任务学到的识别交互先验，因此同样需要将独立 PT 分支学到的未池化交互特征迁移至三元任务。同时，由于呈递 HLA 决定了哪些肽段残基埋入结合槽、哪些暴露给 TCR，迁移强度必须按残基、按 HLA 语境动态调节。

### 5.2 代码实现与双向优化机理（已由消融证实同时提升 PT 与 PHT）

`fused = query + β ⊙ W·LN(z_PT)`，其中 `β = σ(gate([LN(query), LN(z_PT), h̄]))`，逐残基、`h̄` 是 HLA 摘要，偏置初始化为 −2.0（`β ≈ 0.12` 起步，避免未充分训练的 PT 特征污染早期三元路径，`stage_MOE_PT_model.py:26-38`）。该可微设计建立了两条互补路径：

1. **对 PHT 的优化（前向特征迁移 `PT→PHT`）**：把独立 PT 分支经过专家混合后的未池化残基表示 `z_PT` 注入三元路径，由 HLA 条件化逐残基门控 $\beta_i$ 在暴露的识别关键位点打开通道、在无关位点衰减噪声；融合发生在表征空间而非概率空间，避免退化为二元分数乘积或取最小。
2. **对 PT 的优化（反向梯度反馈 `PHT→PT`）**：设 $R(Z_{\mathrm{PT}})=W_{\mathrm{PT}}\mathrm{LN}(Z_{\mathrm{PT}})$、$G=\partial\mathcal{L}_{\mathrm{PHT}}/\partial\tilde U_{\mathrm{PHT}}$，三元损失沿迁移路径直接回传至 PT 表征：
   $$\frac{\partial\mathcal{L}_{\mathrm{PHT}}}{\partial Z_{\mathrm{PT}}} = \left(\beta\,\frac{\partial R}{\partial Z_{\mathrm{PT}}} + R\,\frac{\partial\beta}{\partial Z_{\mathrm{PT}}}\right)^{\!\top} G$$
   直接更新 PT 交叉注意力与 PT 专家参数 $\theta_{\mathrm{PT}}^{\mathrm{rep}}$（独立 PT 分类头仍由 PT BCE 与辅助项更新），通过三条机制提升 PT：（i）**额外三元识别监督**，迫使 $Z_{\mathrm{PT}}$ 保留兼顾二元与三元的判别特征；（ii）**HLA 门控抑制负迁移**——如在 `010`（$y_{\mathrm{PH}}=0, y_{\mathrm{PT}}=1, y_{\mathrm{PHT}}=0$）等不一致样本上降低 $\beta_i$，保护 PT 阳性表征不被三元阴性梯度破坏（区别于无门控直接相加 $\beta\equiv 1$）；（iii）**跨任务表征正则化**，促使 PT 学到跨 HLA 背景更可迁移的肽—TCR 模式（同时明确 PT 推理仍无 HLA 输入）。

### 5.3 相对前人工作

#### Fusion-pMT（Ma et al., 2025）—— 核心洞察的出处

- **已做到**：先在 PH 上预训练，然后丢掉池化与分类头，把**未池化的 pHLA 交互矩阵**当作第二个交叉注意力模块对受体的 query，在三联任务上全参数微调。
- **"三联任务该消费未池化的成对表示、而不是一个分数"这个洞察是他们的，我们不声明。**
- **限制**：单向 PH→PHT；**没有独立受监督的 PT 分支**；第二阶段用三联训练**替换**成对训练。
- **我们的增量**：针对 PHT 的双结合本质补上独立受监督的 PT 分支并逐残基按 HLA 门控注入；三个监督全程保持激活；两条迁移路径可微，实现前向提 PHT、反向提 PT 的双向收益。

#### TranspMHC / TransTCR（Niu et al.，2025）

- **已做到**：把预训练的 pHLA 编码器迁移进识别模型，并加一个 margin 形式的差异目标——比较同一 pHLA 复合物下一个结合受体与一个非结合受体。
- **限制**：它的差异目标在**同一任务内比较两个样本**；没有 PT 分支。
- **关系**：我们的耦合是在**同一样本的三个输出之间**。两者**互补**，我们不替代也不否定它。

#### StriMap（Cao et al., 2026）

- **已做到**：预训练 PH 预测器后**冻结**，当作特征聚合器；在 HLA 侧与肽侧分别用输入相关的门控，把预训练表示与任务特定表示混合；用双线性注意力对残基—残基交互建模，并使用配对 α/β 链与 ESMFold 预测结构。
- **限制**：pHLA 预测器被冻结，信息单向流动，**成对任务无法从三联监督中受益**。
- **我们的增量**：成对交互模块在三联梯度下保持可训练；更重要的是，**我们的门控混合的是"另一个关系"的表示，而不是同一实体的两个表示**（冻结的 vs 任务特定的）。
- **必须直说的对比不对等**：StriMap 还用了配对 α/β 链与预测三维结构，我们没有。**因此不声明"更完整的分子建模"。**

### 5.4 贡献三明确不声明的内容

- 不声明"未池化的成对表示才是三联该消费的东西"这个洞察（Fusion-pMT 的）。
- 不声明分子建模更完整（StriMap 用了结构与配对链）。
- 严格区分梯度作用对象：反向梯度直接更新的是 PT 表征模块 $\theta_{\mathrm{PT}}^{\mathrm{rep}}$ 而非独立的 PT 分类头；PT 推理阶段仍无 HLA 输入，因此不宣称“PHT 把 HLA 条件化判断直接教给了 PT”，而是表述为跨任务表征正则化与受门控调节的反向监督，并在 `tab:ablation2` 中加入 `Detached transfer, sg[Z_PT]` 对照将前向复用与反向梯度反馈剥离开。
- $\beta$ 的分布是一个**可解释性观察**，不是因果证据：$\beta$ 高不等于该残基在物理上参与识别。

## 第六部分 · 贡献四：标签感知的方向性一致性

### 6.1 必要性与相对硬概率层级的优势

- **为什么有必要**：即使共享—专属 MoE 在参数空间缓解了任务冲突、PT→PHT 门控迁移打通了跨分支特征流，三个分类头在独立 BCE 下仍会在**输出与决策空间**产生逻辑自相矛盾（如低 PH 却高 PHT）；而无标签/对称一致性罚项（如 HMCN）在 `010`、`100` 等不一致样本上会反向拉偏原本正确的二元输出。
- **相比硬概率层级约束（如 $\hat y_{\mathrm{PHT}}\le\min(\hat y_{\mathrm{PH}},\hat y_{\mathrm{PT}})$ 或 C-HMCNN 架构投影）的三点优势**：
  1. **尊重独立条件输入与校准差异**：事件包含关系成立，但三头是不同条件输入下各自校准的 sigmoid，用带容差 $m$ 的软平方 hinge 做松弛更符合统计语义。
  2. **避免二元头欠置信引发误差传播**：在数据稀缺的 PT 头或噪声 PH 头对 `111` 正例偏保守时，硬 $\min$ 会强行压低正确的三元预测；软方向性 hinge 在 `111` 上冻结 $\mathrm{sg}[\hat y_{\mathrm{PHT}}]$、温和拉升滞后的二元头。
  3. **逐样本自适应方向**：不同于分类树每条边固定一个方向，四项规则按观测标签类（`111` vs `000`/`010`/`100`）逐样本反转方向。

### 6.2 我们的规则与三机制分工

对每个观测到的标签类，**由标签指定哪一端是参照，对参照端加 stop-gradient，只让"自身标签支持的那一端"动**（表见 1.4 节）：`111` 上以三联为参照拉升 PH 与 PT；`000`/`010` 上以 PH 为参照压低三联；`000`/`100` 上以 PT 为参照压低三联。在整体架构中，它与贡献二（参数/表征空间 MoE 解耦）和贡献三（跨分支特征/梯度流门控迁移）各司其职，专门负责**输出与决策空间**的语义对齐。

### 6.3 相对前人工作

#### HMCN（Wehrmann et al., ICML 2018）—— 函数形式的出处

- **已做到**：平方 hinge 违约罚 `λ·max{0, ŷ_child − ŷ_parent}²`。**这个形式是他们的，我们不声明。**
- **限制**：梯度对称——触发时 child 被压下、parent 被推上，幅度相等；真值标签只通过分类损失进入，**从不进入 penalty 本身**。
- **我们的增量**：标签指定一端为参照，stop-gradient 冻结它，只有被支持的那一端移动。

#### C-HMCNN（Giunchiglia & Lukasiewicz, NeurIPS 2020）—— 最接近的一篇

- **已做到**：**标签感知的梯度路由**——损失在一个 max 内部把预测乘上二值标签，于是标签决定哪些输出有资格接收梯度，max 在其中选出接收者；另有 max-constraint 模块在**架构上**强制层级一致。
- **限制**：一致性是架构性的；方向由**事先给定的分类树边**固定，每条边对所有样本只有一个方向。
- **我们的三点差异（仅此三点）**：
  1. **形式**：我们加软平方 hinge，不施加任何硬约束；C-HMCNN 的一致性是架构性的、标签感知藏在似然里。
  2. **梯度控制机制**：C-HMCNN 用"乘标签"掩掉候选集；我们对标签指定的参照端加**显式 stop-gradient**，该算子仍参与前向取值，只是作为目标被冻结。
  3. **方向由谁决定**（最重要）：HMCN 与 C-HMCNN 沿事先给定的分类树耦合，每条边一个方向；**我们的方向是逐样本从观测到的标签模式里选出来的**——同一对输出头在 `111` 与 `010` 上的方向相反。

### 6.4 贡献四明确不声明的内容

- 不声明平方 hinge 形式是我们的（HMCN）。
- 不声明"标签感知的梯度路由"这个想法是我们的（C-HMCNN）。
- **不写"据我们所知首次"**，直到对非对称 stop-gradient 这一族（mean teacher、BYOL、SimSiam、R-Drop）以及更晚的逻辑约束工作做完检索。目前这条在论文里按"差异在这三点上，其他地方不差异"的措辞写。
- 不声明软约束保证最终二分类严格一致（见 7.3）。
- 辅助 BCE 的收益必须与一致性正则的收益**分开报告**（已有两个开关可做）。

## 第七部分 · 论证上最需要修的三个问题

### 7.1 `110` 不存在，三联在语料上几乎是冗余的（最高风险）

**事实**：合法标签集是 `{000, 010, 100, 111}`，校验器见到 `110` 直接抛错（`stage_MOE_consis_loss.py:41-46`）。

**后果**：在每一条可用样本上，`PHT ≡ PH ∧ PT` 恒成立。于是一个审稿人可以合理地问：既然三联标签是两个成对标签的确定函数，为什么需要一个三联头？启发式组合（`min(p_PH, p_PT)` 或 `p_PH · p_PT`）就已经是正确答案。

**当前的缓解（已写进论文）**：
1. 引言贡献一正面从 `110`/`111` 数据不对称出发论证显式三元建模的必要性，Limitations 框第一条如实交代当前语料的标签限制，前后口径一致；
2. 主结果表与消融表把 `s_min` / `s_prod` 两种启发式组合**作为正式对照行**，并配 `100 vs 000` / `010 vs 000` 诊断列，这是唯一公平的基线；
3. 明确把"获取 `110` 样本"列为首要未来工作。

**`110` 何时有意义**：肽被呈递、受体在序列层面也像能识别，但三联实际不结合——构象不兼容、动力学不稳定、或该受体的识别依赖另一个等位基因背景。这类样本正是"必要但不充分"的唯一可检验证据。**没有它，贡献四的四条 hinge 里只有三类标签被用到，"方向性"的价值无法被完整检验。**

### 7.2 事件包含关系不能直接推出三个预测头的概率序关系

`P(三联结合) ≤ P(呈递)` 在**事件**层面成立，但三个头输出的是三个独立校准的 sigmoid，不是同一概率空间上的边缘与联合。所以不能把 hinge 写成"概率必须满足层级"的推论，只能写成"我们把一个已知的事件关系**松弛**成一个可微的罚项"。论文目前按后者措辞，不要改回前者。

与之配套：报告 AUROC/AUPRC 的同时必须报告 **Brier 与 ECE**，否则无法区分"一致性改善了排序"和"一致性只是把概率整体压低了"。

### 7.3 软约束不保证最终二分类结果严格一致

阈值是在验证集上按 MCC 最优**冻结**下来的，三个头各自一个阈值。软 hinge 不保证 `1[p_PHT > θ_PHT] ≤ 1[p_PH > θ_PH]`。所以**不能声明"输出一致"**，只能声明"违约率下降"。相应地，Results 里需要报告**违约样本占比**这个量，而不是只报指标。
